# Agents Rubric — 산출물 품질 평가 기준

> 본 문서는 `reviewer` 에이전트가 다른 에이전트 산출물을 검증할 때 사용하는 **1차 기준**입니다.
> 각 에이전트는 본인 산출물을 본 기준에 맞추도록 자가검토하세요.
> 절차·판정 규칙(PASS/HOLD/FAIL)은 `agents/reviewer.md` 참조.

---

## 0. 공통 기준 (모든 에이전트 공통)

| 항목 | 합격 기준 |
|------|----------|
| 요청 범위 준수 | 시키지 않은 자체발의 변경 없음 |
| 증거 첨부 | grep/read/실행 결과 또는 출처 URL 포함 |
| 한국어 우선 | 사용자 대면·보고는 한국어 (코드 식별자는 영문 유지) |
| 브랜드 용어 | UI=`타입/Type`, 코드 내부=`faction` (CLAUDE.md 정책) |
| 모호성 처리 | 추정 시 "추정" 또는 "확인 필요" 명시 |
| 핸드오프 명시 | 다음 lane 필요성을 보고에 표기 |

## P2 — Priority 2 품질 게이트 (세무 추정·진단·카드 데이터 공통)

세무 도메인 산출물(특히 `filing-estimator`, `tax-domain-expert`, `diagnostic-builder`)에 적용되는 **강제 규칙**. 위반 시 reviewer 즉시 FAIL.

| P2 항목 | 합격 |
|---------|------|
| 가짜 데이터 차단 | 출처 없는 수치·창작 데이터 없음 |
| ★ 신뢰도 의무 | 모든 추정 라인에 ★/★★/★★★ 표기 |
| 단서 출처 의무 | 추정마다 단서(evidence) 출처 명시 |
| 단정 표현 금지 | "신고 누락 확정", "X 무조건 됨" 등 단정 없음 |
| 사실 vs 추정 구분 | 1차 출처 확인 사실은 별도 표기, 추정과 혼동 금지 |
| 개인 식별정보 차단 | 사업자번호·이름·연락처 외부 호출·DB 저장 없음 |

## 1. coordinator 산출물

| 평가 항목 | 합격 |
|----------|------|
| 분해 명시 | 의도·산출물·위험도·검증기준 4항 기록 |
| 라우팅 적합 | 라우팅 결정표 기준 부합 (잘못된 lane 할당 없음) |
| 병렬화 | 의존성 없는 task는 단일 메시지 다중 Agent 호출 |
| 검증 게이트 | 위험도 트리거(세법·추정·진단·외부 시스템) 시 reviewer 호출 흔적 |
| 보고 형식 | ✅완료/📂변경/🔍검증/❌막힘/👉다음 구조 |
| 사용자 결정 부담 | 자율 결정 가능 항목을 사용자에게 묻지 않음 |
| 도메인 위임 | 세법·추정·진단을 본인이 직접 산출하지 않음 |

## 2. code-implementer 산출물

| 평가 항목 | 합격 |
|----------|------|
| 요청 정확 이행 | 명시 변경만 (자체발의 청소·리팩터 없음) |
| 한·영 동시 반영 | 사용자 대면이면 `index.html` ↔ `en.html` 동기 |
| 브랜드 용어 | UI=`타입`, CSS/JS 식별자=`faction` 유지 |
| 형식 유효 | HTML/JSON 파싱 가능 |
| 검증 증거 | grep 결과 또는 형식 체크 명령 포함 |
| 카피 창작 | 본인이 사용자 대면 카피 작성하지 않음 (doc-writer 데이터 사용) |
| 핸드오프 | reviewer/deployer 호출 필요성 명시 |

## 3. doc-writer 산출물

| 평가 항목 | 합격 |
|----------|------|
| 톤·분량 | 가이드 부합 (퀴즈 카피 80~150자, 면책 최소, 기획서 200~400자/섹션, 블로그 1,200~2,000자) |
| 사실 검증 | 통계·날짜 출처 URL + 날짜 표기 |
| 법률 체크 | 어필리에이트 고지·면책·상표 안전 |
| 이중 언어 | 한·영 분기 일관성 (한쪽만 갈 때 사유 명시) |
| 금지 표현 회피 | "혁신적", "최고의", 이모지 남발 없음 |
| 마크다운 형식 | 헤딩·표·링크 깨짐 없음 |
| 세법 인용 출처 | tax-domain-expert 산출 데이터 인용 (자체 창작 금지) |

---

## 4. researcher 산출물

| 평가 항목 | 합격 |
|----------|------|
| 압축 | 핵심만, 원문 통째 없음 |
| 출처 | path:line 또는 URL + 발행/접속 날짜 |
| 신뢰도 | 높음/중간/낮음 표기 |
| 3-쿼리 룰 | 3회 실패 시 멈춤·"확인 불가" 보고 |
| 의견 배제 | 추천·판단 없음 (사실만) |
| 시크릿 안전 | 외부 호출에 식별정보·과세정보 포함 안 함 |
| 매트릭스 발굴 (해당 시) | 셀 정의·셀당 임계 3건·빈 셀 식별·중복 회피 명시 |

## 5. reviewer 산출물

| 평가 항목 | 합격 |
|----------|------|
| 판정 명확 | PASS / HOLD / FAIL 중 하나 |
| 근거 첨부 | 각 항목별 path:line 또는 명령 결과 |
| 독립성 | 본인이 작성한 산출물 검토 아님 |
| 위계 적용 | 보안·법률·**P2 위반** → FAIL, 톤·오타 → HOLD |
| 간결 | PASS면 한 줄도 OK |
| 권한 경계 | 수정 시도 없음 (수정은 호출 lane에 재위임) |
| P2 게이트 적용 | 세무 도메인 산출물에 P2 체크리스트 전수 적용 |

## 6. tax-domain-expert 산출물

| 평가 항목 | 합격 |
|----------|------|
| 조항 정확 | 조문 번호·시행일·개정일 표기 |
| 원본 확인 | law.go.kr 또는 동등 1차 출처 흔적 (WebFetch 흔적) |
| 요건 분해 | 대상·기간·한도·중복적용·신고의무 점검 |
| 판례·예규 | 사건번호·문서번호·선고/생산일 정확 |
| 청구 근거 (경정청구 시) | 국기법 §45조의2 ① 일반 / ② 후발 명시 |
| 시효 카운터 | 5년 일반 / 3개월 후발, 시작일 포함 |
| 계산 투명 | 한도·이월·공제 순서 표 형태, 단위 통일 |
| 면책 포함 | "확정 자문 아님, 개별 사실관계 추가 확인 필요" |
| 단정 회피 | "X 무조건 됨" 금지, "요건 충족 시 적용 가능" 형식 |
| 정보 안전 | 고객 식별·과세 정보 외부 호출 포함 안 함 |
| 카피 미창작 | 사이트 표시용 카피는 doc-writer에 데이터만 전달 |
| 추정 미산출 | ★ 신뢰도 추정은 filing-estimator에 위임 |
| 진단 미설계 | yes/no 진단 문항은 diagnostic-builder에 위임 |

## 7. filing-estimator 산출물 (P2 게이트 핵심)

| 평가 항목 | 합격 |
|----------|------|
| **★ 신뢰도 의무** | **모든 추정 라인에 ★/★★/★★★ 표기 (P2)** |
| **단서 출처 의무** | **추정마다 단서(재무제표·공시·계약서·업종 디폴트) 출처 (P2)** |
| **가짜 데이터 차단** | **출처 없는 수치·창작 데이터 없음 (P2 — 위반 시 즉시 FAIL)** |
| 단정 표현 금지 | "신고 누락 확정" 금지. "★★ 추정 — 신고서 확인 필요" 형식 |
| 반례 점검 | counter-signal 섹션 있음 ("이게 있으면 추정 무효") |
| 신뢰도 등급 일관 | ★(간접 1개) / ★★(직접 2개+) / ★★★(1차 단서 직접) |
| 트리아지 사유 | R/A/B 등급별 한 줄 사유 |
| 시그널 DB 참조 | 기존 매핑이 있으면 ★ 디폴트 적용 흔적 |
| 신규 매핑 권고 | 새 패턴 발견 시 "DB 업데이트 권고" 섹션 |
| 정보 안전 | 사업자번호·이름 외부 호출 없음 (공시 자료는 OK) |
| 조문 미인용 | 조문·판례 자체 인용 없음 (tax-domain-expert 위임) |
| 면책 포함 | "본 추정은 가용 단서 기반 개연성 분석, 확정은 실제 신고서 확인 후" |

## 8. diagnostic-builder 산출물

| 평가 항목 | 합격 |
|----------|------|
| 카드 정의 인용 | tax-domain-expert가 정의한 조문·요건 인용 |
| yes/no 명확 | 모든 문항이 명확한 yes/no, 모호 표현 없음 |
| 단일 사실 | 한 문항 한 사실 (복합 질문 없음) |
| 클라이언트 응답 가능 | 전문 용어 최소화, 응답 가능한 구체성 |
| 채점 매핑 명시 | 답 조합별 등급(R/A/B 등) 정의 |
| 후속 액션 한 줄 | 등급별 후속 액션 명시 |
| 채점 불가 옵션 없음 | "잘 모름", "경우에 따라" 답 없음 ("확인 필요"로 별도 처리) |
| 문항 수 적정 | 3개 권장, 최대 5개 |
| ★ 미산출 | 신뢰도 ★ 산출은 filing-estimator 위임 |
| 조문 미인용 | 조문 자체 인용은 tax-domain-expert 위임 |

## 시그널 DB 운영 (filing-estimator / tax-domain-expert / researcher 공통)

`.claude/SIGNAL_DB.md` 메타 스펙 기반.

| 평가 항목 | 합격 |
|----------|------|
| 참조 흔적 | 추정·매트릭스 발굴 시 기존 매핑 참조 흔적 |
| 신규 매핑 권고 | 새 패턴 발견 시 보고에 "DB 업데이트 권고" 섹션 |
| evidence_sources 비어있지 않음 | 신규 매핑 권고 시 단서 출처 ≥1개 |
| case_id 외 식별정보 없음 | 사업자번호·이름 등 저장 권고 없음 |
| validation_record 정합 | 누적 결과가 ★ 신뢰도와 일치 |
| 3건 룰 | ★ 상향 권고 시 검증 누적 3건 이상 흔적 |
| 반례 즉시 하향 | counter-signal 발견 시 ★ 1단계 하향 권고 |

## 위계 (Severity)

| 등급 | 예시 | reviewer 판정 |
|------|------|--------------|
| **BLOCKER** | 시크릿 푸시, 잘못된 세법 조항 인용, 프로덕션 미승인 배포, 어필리에이트 고지 누락, 고객 정보 외부 송출, **P2 위반(가짜 데이터·★ 없는 단정·단서 없는 추정)** | **FAIL** |
| **MAJOR** | 한·영 동기 누락, 면책 누락, 트래킹 파라미터 누락, 자체발의 리팩터, 헬스체크 누락, **청구 근거 조문 누락, 시효 카운터 누락, 진단 채점 매핑 누락** | **HOLD 또는 FAIL** |
| **MINOR** | 톤 어색, 단어 선택, 사소한 마크다운 깨짐, 출처 날짜 누락, **시그널 DB 업데이트 권고 누락** | **HOLD** |
| **TRIVIAL** | 띄어쓰기, 코멘트 누락 | 참고만 (PASS 가능) |

## 자가검토 체크리스트 (각 에이전트 보고 직전 1회)

1. [ ] 시킨 범위만 변경했는가?
2. [ ] 증거(grep/read/실행/URL+날짜)를 첨부했는가?
3. [ ] 사용자 대면이면 한·영 동기·법률 체크 통과했는가?
4. [ ] 세법 인용이면 1차 출처(law.go.kr 등)와 시행일·면책이 있는가?
5. [ ] 배포면 시크릿 점검·헬스체크·롤백 명령 있는가?
6. [ ] **세무 추정·진단이면 P2 게이트 통과했는가? (★ 신뢰도·단서 출처·가짜 차단)**
7. [ ] **경정청구 작업이면 청구 근거 조문(국기법 §45조의2 ①/②)·시효 카운터 명시했는가?**
8. [ ] **시그널 DB 관련이면 신규 매핑 권고 / 기존 참조 흔적 있는가?**
9. [ ] 다음 핸드오프 lane을 보고에 명시했는가?
10. [ ] 보고가 한국어로 압축됐는가?
